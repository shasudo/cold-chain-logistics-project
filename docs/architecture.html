What happens in each component

#ComponentWhat happens inside
1Data sourcesGPS coordinates, truck sensors, IoT temperature (°C) and route telemetry stream off the fleet. In this project they arrive as one hourly CSV (Southern California, Jan 2021–2024) standing in for the client's live legacy feed.
2Legacy SQL Server
scripts/ingest_legacy_data.py · Phase 0		The script loads the CSV, renames 9 columns to cryptic legacy names (timestamp→TS_UTC, iot_temperature→IOT_TEMP_VAL_C…), stamps every row SYS_INGEST_FLAG='Y', and bulk-loads it with to_sql(if_exists='replace', schema='dbo') into dbo.TBL_SC_FLEET_HIST_RAW. Your server holds 32,065 rows.
3BI dashboard (legacy)The old way of "chatting with data": hand-written SQL and static charts. The video calls out why it fails — manual analysis, no live weather, no SOP knowledge, no record of who asked what.
4Secure view + logins
scripts/setup_security_and_view.sql · Phase 2		Creates schema FDE_VIEWS and view VW_ACTIVE_FLEET translating junk names back to English (Timestamp, Latitude, Current_Temperature_C…). Creates login USR_FDE_RO with SELECT on the view only; raw table reads and all dbo writes are explicitly DENIED — this is what stops LLM hallucinations from touching real data.
5SOP ingest → Pinecone
scripts/ingest_sop_pinecone.py · Phase 1		Parses every .md/.txt/.pdf/.csv/.xlsx under data/policy/, chunks markdown by headers then into 600-char pieces (60 overlap), embeds them (OpenAI 1536-dim fde-sop-index-openai or local BGE-M3 1024-dim fde-sop-index-local, serverless aws/us-east-1) and upserts with IDs like SOP-chunk-12. An md5 hash cache re-ingests only changed files and purges vectors of deleted ones.
6Agent tools
src/agent_tools.py · Phase 3		query_telemetry_db — runs the LLM's T-SQL against the view only, rejects anything not starting with SELECT, returns max 10 rows, all under the read-only agent login. fetch_corridor_conditions — calls the Open-Meteo REST API for live temperature/wind at the truck's GPS and derives a congestion index (wind > 10 km/h → High Transit Disruption). search_compliance_sop — Pinecone retriever (top-2 chunks with source-file metadata) for thresholds, breach mitigations, rerouting rules.
7Orchestrator
src/orchestrator.py · Phase 3		A LangGraph loop with two nodes: reasoner (the LLM, bound to the 3 tools) ⇄ tools (executes calls, returns outputs for another reasoning pass). Brain is switchable via Agent_llm: OpenAI gpt-4o, DeepSeek, or local Ollama qwen2.5:7b. MemorySaver keeps per-session threads. The system prompt forces the order telemetry → weather → SOP and a fixed business format: Executive Summary → Telemetry table → Action Plan with SOP citation. Run standalone for the Phase-3 CLI test.
8Streamlit UI + audit
src/ui.py · Phases 4–5		Dispatch Console chat: each user gets a UUID session thread; every tool call, tool output and final answer streams live with expandable traces and is silently INSERTed into FDE_VIEWS.AgentAuditLog (SessionID, NodeExecuted, ToolName, Content) using agent credentials (which hold INSERT rights on that table only). Security & Audit Logs view replays the trail but only after an admin gate comparing input against SQL_ADMIN_USER/PASSWORD from .env.
9Deploy
.github/workflows/deploy.yml · Phase 6		Manual GitHub Actions run SSHes into the server (EC2_HOST/USER/KEY secrets), git pulls main and restarts the systemd streamlit service. On your VPS the same flow targets oracle-stock paths.
